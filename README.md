# LaterWatch — 跨平台视频稍后再看侧边栏插件

一款 Chromium 内核浏览器的 Manifest V3 侧边栏扩展，聚合 **B 站 / 抖音网页视频 / 本地视频** 三类资源，以浏览器侧边栏为载体进行统一管理，并提供 **回收站式删除机制**，避免误删。

> 仅做片单管理，不提供视频下载、解析、转码等功能。

## 开发目的

- 解决「稍后一定要看哪些视频」的管理问题；
- 收藏感兴趣的视频，留到空闲时再统一观看；
- 将不同平台的稍后看视频集中到浏览器侧边栏统一管理；
- 为平台稍后再看的视频添加时间锚点，方便定位上次观看到的位置或视频中的关键内容时间点。

---

## 功能特性

### 侧边栏主界面
- 点击浏览器扩展图标唤起侧边栏，与网页内容并排展示。
- **当前视频信息卡片**：自动识别当前活动标签页的视频（B 站 / 抖音），展示封面、标题与平台标识，支持一键加入待看。卡片内容会随 SPA 导航实时更新。
- **统一待看列表**：按添加时间倒序展示所有条目，单条包含封面、标题、来源平台标识与操作按钮。
- **平台筛选**：顶部提供「全部 / B站 / 抖音 / 本地视频」切换标签；切换到当前视频所属平台时会自动过滤。
- **拖拽排序**：长按条目进入拖拽模式，仅重排当前可见条目，其余平台/回收站条目位置不变。
- **当前视频高亮**：列表中与当前标签页相同的视频会高亮并自动滚动到可视区域。

### 网页快捷添加入口
- 仅在 B 站、抖音域名下自动注入内容脚本，其他网站不触发。
- 鼠标悬浮视频封面时，封面左上角出现「稍后再看」悬浮按钮，点击即添加。
- 已在待看列表中的视频，按钮变为「已添加」禁用态。
- 添加成功后伴随轻量 toast 提示，侧边栏列表实时刷新。
- 支持右键菜单「添加到稍后再看」（仅在视频详情页显示）。

### 多平台视频管理

| 平台 | 添加方式 | 数据存储 | 跳转播放 |
| --- | --- | --- | --- |
| B 站 | 页面悬浮按钮 / 右键菜单 | 浏览器本地 | 新开标签页，已打开则复用 |
| 抖音 | 页面悬浮按钮 / 右键菜单 | 浏览器本地 | 新开标签页，已打开则复用 |
| 本地视频 | 侧边栏「导入本地视频」 | 浏览器本地 | 侧边栏内浏览器播放器播放 |

> 抖音无开放 API，元数据仅保存在当前浏览器本地，不同步抖音账号收藏。

### 评论与时间锚点
- 每个条目可添加一条评论，评论文本中形如 `02:15`、`1:02:15` 的时间片段会自动渲染为可点击锚点。
- 点击锚点可让已打开的视频播放器跳转到对应秒数（`HH:MM:SS` / `MM:SS` 均支持，分钟/秒 ≥ 60 视为非法）。
- 回收站中的评论只读展示，时间锚点不参与跳转。

### 回收站式删除机制
- 待看列表中点击删除，条目移入回收站，底层数据保留。
- 回收站支持 **单条恢复** / **单条永久删除** / **清空回收站**。
- 永久删除前弹出二次确认弹窗，操作后数据不可恢复。
- B 站、抖音、本地视频三类条目均遵循该机制。

## 开发指南

### 环境要求

- Node.js `>= 20.19.0`
- Chromium 内核浏览器 `>= 114`

### 安装与启动

```bash
# 安装依赖
npm install

# 启动开发服务（产物输出到 dist/，支持热更新）
npm run dev
```

### 加载扩展

1. 打开浏览器扩展管理页：`chrome://extensions`
2. 开启右上角「开发者模式」
3. 点击「加载已解压的扩展程序」，选择项目下的 `dist/` 目录
4. 点击扩展图标即可唤起侧边栏

> 扩展重新加载后，已打开的 B 站 / 抖音页面需要手动刷新，内容脚本才会重新注入。

### 构建生产版本

```bash
# 类型检查 + 构建
npm run build
```

## 数据存储

所有插件数据均存储在 `chrome.storage.local`，键名统一加 `lw:` 前缀：

| 键 | 内容 |
| --- | --- |
| `lw:watch-list` | 待看列表与回收站条目（统一数组，`deletedAt` 区分） |
| `lw:settings` | 插件配置项（预留） |

- B 站 / 抖音 / 本地视频的元数据与回收站数据均仅保存在当前浏览器本地，不上传任何第三方服务器。
- 清理浏览器数据或更换设备会导致本地数据丢失。
- 所有写入操作由 **background Service Worker** 作为唯一处理方，避免多端写入冲突。

### 视频去重规则

待看条目的唯一 ID 采用 `platform:videoId` 格式：
- B 站：`bilibili:BVxxxxxx` 或 `bilibili:avxxxxxx`
- 抖音：`douyin:1234567890123456789`
- 本地视频：`local:<本地标识>`

同一视频通过不同入口添加只入库一次；已在回收站中的视频重新添加会自动恢复并置顶。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 本地存储插件数据 |
| `sidePanel` | 侧边栏能力 |
| `activeTab` | 当前标签页操作（提取视频信息、seek 控制） |
| `contextMenus` | 右键菜单「添加到稍后再看」 |
| `https://*.bilibili.com/*` | B 站内容脚本注入 |
| `https://*.douyin.com/*` | 抖音内容脚本注入 |

仅在 B 站、抖音域名下注入内容脚本，不读取其他网站的页面内容与用户数据。

## 核心设计约定

- **样式隔离**：内容脚本注入的按钮与 toast 统一使用 `lw-` 类名前缀与独立根 ID，不修改宿主页面原有 DOM 结构。
- **事件委托**：网页悬浮按钮采用 `mouseover` 事件委托监听，通过 `a[href*="/video/"]` 反查封面元素，不依赖平台类名，降低页面改版导致失效的风险。
- **唯一写入方**：所有 `watchList` 存储写入统一由 background 处理，内容脚本与侧边栏只通过消息通信请求写入。
- **SPA 导航感知**：内容脚本运行在隔离世界，无法劫持页面自身的 `history.pushState`，采用 500ms 轮询 `location.href` + `popstate` 监听的方式感知视频 ID 变化。
- **元信息补报**：视频 ID 变化后，标题/封面可能晚于 URL 更新，因此在 ID 变化后 3 秒内持续观察并补报，避免新视频沿用旧元信息。
- **封面提取优先级**：依次尝试 `og:image`（property/name）、`lark:url:video_cover_image_url`（B 站标准、抖音无 og:image 时使用其专属属性）。

## 边界与约束

1. **平台接口约束**：抖音无开放 API，仅能保存链接与基础元数据，无法接入抖音账号体系。
2. **浏览器限制**：本地视频仅支持用户手动选择导入，无法自动扫描磁盘；部分小众视频格式可能不支持浏览器内置播放。
3. **数据范围**：插件本地数据仅保存在当前浏览器配置文件中，不跨设备同步。
4. **扩展重新加载**：已打开的宿主页面需要手动刷新才能重新注入内容脚本。
